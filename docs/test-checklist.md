# 发版测试清单

每次发版前照着执行的标准流程。**这份文档是通用的，不记录任何一次的实测数值**；
某个版本的实测结果、截图与失败项根因记在
[`docs/test-report.md`](test-report.md)（当前存档的是 3.4.0）。

**共 109 个测试点，其中 22 项必须在真机上人工完成**（触摸板手势、实体键帽、系统侧设置，
adb 一律模拟不了）。

两份文档的分工：

| 文档 | 内容 | 什么时候写 |
|---|---|---|
| 本文档 `test-checklist.md` | 测什么、怎么测、预期是什么 | 增删功能时更新 |
| [`test-report.md`](test-report.md) | 某个版本照着测出来的结果 | 每次发版另存一份 |

## 一、快速冒烟测试

只改了代码、**没动 `app/src/main/assets/shared/`** 的小版本，跑完这 8 项即可发版：

| | 测试点 | 判据 |
|---|---|---|
| ☐ | **A2** 单元测试 | `testDebugUnitTest` 全绿 |
| ☐ | **A5** 权限表 | `aapt2 dump badging` 无 `INTERNET` |
| ☐ | **B1** 全新安装不重建词库 | 日志无 `round #` |
| ☐ | **C1** 普通文本框 | 贴功能行 `rime_ice` |
| ☐ | **D1** 功能行完整 | 11 键齐全 |
| ☐ | **D6** 候选行 | 10 个候选铺满一行 |
| ☐ | **H1** 版本号 | 关于页与 `versionName` 一致 |
| ☐ | **I1 / I2** 飞字横滑 + 上滑 | 高亮跟着动、上滑上屏 |

**动过 `assets/shared/` 就不能只跑冒烟** —— 必须整跑 **B 节「全新安装与零部署」**，
否则用户首次启动会卡两分多钟重建词库（README「给 AI 的说明」第 1 节）。

## 二、测试方法（必须遵守）

### 1. 按控件文本定位，不用固定坐标

```
uiautomator dump        取控件树
  → 按 text / resource-id 匹配目标节点
    → 读它的 bounds，算中心点
      → input tap <cx> <cy>
```

**匹配不到目标控件即报错中止，不要退化成猜坐标。**
此前用固定坐标盲点曾误触拨号盘、弹出「选择 SIM 卡拨打电话」（见测试报告「方法」一节）。

### 2. 判断键盘是否渲染必须看截图

键盘是画出来的，**不在无障碍控件树里**。用 `uiautomator dump` 找 `Esc`、找候选词，
永远找不到，会得出「功能行没恢复」这类错误结论。

判定键盘状态只有两个可信手段：

- `screencap` 截图后人眼看
- `logcat` 里 `Switched to keyboard:` 这行日志（只能证明贴了哪个键盘，不能证明画出来了）

### 3. 驱动脚本

驱动脚本 `ui.py` 未随仓库分发 —— 它依赖特定的设备地址与屏幕状态。需要时按上面第 1 条重建。

### 4. 记录结果

每次发版把本清单的执行结果另存为一份 `test-report.md`（覆盖上一版），
失败项写清**根因或截图**，不要只写「不通过」。

## 五、键盘路由（C）

用配套的网页测试台 [`tools/ime-test/index.html`](../tools/ime-test/index.html)：13 种输入框，
每个都标了预期出现哪个键盘，另有实时按键日志与一键导出报告。
拷到手机上 `file://` 打开，或 `python3 -m http.server` 起临时服务。

预期值来自 `KeyboardWindow.onStartInput()`：
`NUMBER/PHONE/DATETIME → guyii_num`；`TEXT` 且变体为 `EMAIL/PASSWORD/WEB_EMAIL/WEB_PASSWORD` →
`guyii_ascii`；其余 → `.default` → `smartMatchKeyboard()` → `rime_ice`。

**逐个点进输入框，截图看贴的是哪个键盘**（也可对照 logcat 的 `Switched to keyboard:`）。

| ☐ | C2 | `<textarea>` 多行文本 | 功能行 `rime_ice` | 🤖📷 |
| ☐ | C3 | `type="search"` 搜索框 | 功能行 `rime_ice` | 🤖📷 |
| ☐ | C4 | `type="password"` 密码 | 英文行 `guyii_ascii` | 🤖📷 |

| ☐ | C9 | `inputmode="numeric"` | 数字行 `guyii_num` | 🤖📷 |
| ☐ | C10 | `inputmode="decimal"` | 数字行 `guyii_num` | 🤖📷 |

## 十一、已知冲突回归项（J）

这些设置项与本项目的设计直接冲突。每次发版**逐条确认状态没有变回去**。
详细说明见 [测试报告](test-report.md)的「设置与本项目设计的冲突」一节。

| | # | 设置项 | 冲突点 | 应处于的状态 | 方式 |
|---|---|---|---|---|---|
| ☐ | J1 | **隐藏输入工具栏** | 把整个输入条设为 `GONE`，候选行在其中 —— 等于同时废掉候选与飞字 | 该设置**已移除**，确认设置页里找不到它 | 🤖 |
| ☐ | J2 | **显示候选词窗口** | 四个选项中只有 `Disable` 可用（`InputDeviceManager.kt`：`DISABLED → useVirtualKeyboard = true`），其余三项会让功能行在使用实体键盘时消失、输入法退化为空壳 | 默认值仍是 `Disable`；改成其它值后**能改回来** | 🤖📷 |
| ☐ | J3 | **横向候选词样式** | 显示 `Never fill width`，实际是填满的 —— 为飞字把该分支 `flexGrow` 由 0 改为 1 所致，设置名与行为不符 | 行为符合飞字需要（候选铺满），设置名不符属**已知**；若改过 `CompactCandidateDelegate` 需重测 D6 | 🤖📷 |
| ☐ | J4 | **切换中英文模式时显示提示** | 提示写进编码区，无编码时不渲染，实测看不到 | 已由常驻的 `中`/`英` 键替代（D9）；该提示不显示是**预期** | 🤖📷 |
| ☐ | J5 | **每行最大候选词数** | 仅在「自动填充」样式下生效，默认样式下本就不起作用 | 无需处理，确认改它不影响候选行 | 🤖📷 |
| ☐ | J6 | 四个「拦截 Ctrl+X/C/V/A」 | 曾误判为与实体键盘冲突。**实际只对软键盘按键生效**，实体键盘走 `onKeyDown` 完全不经过；四项默认均为 `false` | 保持默认 `false`；功能行的复制/粘贴正常（D10） | 🤖📷 |
| ☐ | J7 | 系统 Flick typing 开关 | 只对出厂的 Kika 键盘生效，开着可能抢走手势 | 保持关闭（见 I0） | 👤 |
